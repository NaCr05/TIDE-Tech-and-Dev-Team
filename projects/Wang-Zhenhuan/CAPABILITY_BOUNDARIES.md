# 系统能力边界说明

## 当前能够稳定处理

- 文本答案、代码片段和结构化表单式文本；
- 单份答案的结构化基础报告；
- 完整性与正确性初步判断；
- 主要问题和修改建议；
- 0–100 分及 A–F 等级；
- 教师确认、修改和重新评估；
- Agent 失败后保留学生提交；
- Mock 模式下可重复、离线的演示结果。

## 当前不能稳定处理

### 1. 任意数据结构题的语义理解

Mock 规则主要围绕单链表反转样例。面对栈、队列、树、图等题目时，可能因没有命中特定关键词而低估正确答案。

### 2. 代码真实性验证

系统不会编译或运行学生代码，也没有沙箱和隐藏测试。因此不能确认：

- 代码能否编译；
- 运行结果是否正确；
- 是否超时或超内存；
- 边界输入是否通过。

### 3. 同义表达

正确答案如果使用纯中文或不同变量名，Mock 可能无法识别。例如“不出现 prev/current/next，但语义正确”的链表反转答案会被误判。

### 4. 关键词欺骗

错误或不可执行的内容只要包含高分规则需要的关键词，也可能获得较高分。

### 5. 在线模型稳定性

DeepSeek 模式虽然有结构校验和一次重试，但仍可能受到：

- 网络；
- API 限流；
- 模型版本；
- 输出随机性；
- 提示词理解偏差

的影响。

### 6. 权限与生产安全

当前只实现教师和学生操作路径区分，没有完整 JWT、会话权限和生产级鉴权。Slash Command 依赖 Mattermost Token 校验，只适合本地验收 Demo。

## 风险控制

- AI 结果标明仅供辅助；
- 教师拥有确认、修改和重新评估权；
- 每次重新评估和修改会更新状态及版本；
- Agent 失败不会删除学生提交；
- 输出需经过后端结构校验；
- 测试中保留误判，不隐瞒边界。

## 已记录的真实误判

“栈的括号匹配”答案正确描述了压栈、匹配和复杂度，但 Mock Agent 初评为 55/F。教师通过工作台改为 95/A，随后又成功要求重新评估。

该案例证明：

1. Agent 不能取代教师；
2. 教师审核流程是必要功能；
3. 系统能保存并展示评估版本变化；
4. 当前 Mock 规则不具备跨题型的通用理解能力。
